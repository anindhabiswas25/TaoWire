# Contributing

Thank you for helping with TaoWire. This page covers the development setup, the checks every change
must pass, and the rules that are easy to get wrong. Report security problems privately, never in a
public issue or pull request (see [SECURITY.md](SECURITY.md)).

## Setup

| Tool | Needed for |
|---|---|
| [uv](https://docs.astral.sh/uv/), Python 3.10–3.14 | the Python package (the reference implementation) |
| [just](https://just.systems/) | running the gates (optional: every recipe is a plain shell command in the `justfile`) |
| Node.js 20 or 22 | `typescript/` |
| Go (the pinned toolchain from `scripts/go_tools.sh`; `go.mod` keeps `go 1.22` for users) | `go/` |
| Rust 1.80+ with `cargo-audit` | `rust/` |
| Docker | the local chain and Redis for the localnet, abuse and real-Redis tests |

```bash
just setup              # cd python && uv sync --all-extras
just go-tools           # staticcheck and govulncheck, built into .tools/go/bin (repo only)
```

TypeScript dependencies are installed by the recipes that need them (`npm ci` when `node_modules` is
missing or stale).

## Checks

There is no hosted CI: the `justfile` is the gate. Before every commit, run:

```bash
just check              # lint + strict type checks + tests + conformance, all four languages
just migration-test     # compat / migrate / v10 wire tests (live interop with bittensor 10.5.0)
just coverage           # >= 90% on auth/, policy/, limits/, extensions/legacy_v10/,
                        # extensions/response_sig.py, compat/; >= 80% elsewhere
just audit              # pip-audit, npm audit, govulncheck, cargo audit
```

Changes to the request pipeline, streaming, the chain gateway or the v10 bridge also need the
end-to-end checks on a local chain:

```bash
just localnet-up        # Docker subtensor localnet (netuid 2, dev wallets in ~/.taowire/localnet)
just localnet-test      # miner and validator end to end, timelocked weights, TLS, streaming, MCP
just mixed-fleet        # v10 and TaoWire nodes on the same subnet
just interop            # four-language matrix: every miner language, every client signer
just abuse              # attacks on a real 2-worker miner with Redis (TAOWIRE_TEST_REDIS_URL)
scripts/localnet_down.sh
```

Single Python test: `cd python && uv run pytest tests/unit/test_verifier.py::test_name -q`. Python tests
run with warnings as errors, so a new warning fails the suite.

After editing anything in `docs/` or `.env.example`, run `cd python && uv run python ../scripts/sync_mcp_data.py`:
the MCP server ships a copy of both, and `tests/unit/test_mcp_knowledge.py` fails while they differ.

## Coding rules

- **ADR-0001 (one chain client).** Only `chain/gateway.py` performs chain operations. `auth/*` may import
  `bittensor.http_auth`, `bittensor.signing` and `bittensor.sp_core`; `crypto.py` may also import
  `bittensor.keyfiles` (`Keypair`) and `bittensor.wallet` (`Wallet`). No other module imports `bittensor`.
  import-linter and `tests/unit/test_architecture.py` enforce this.
- **Secure by default.** A setting that weakens a default must start with `TW_UNSAFE_` or be clearly
  bounded (spec 16.2); it is logged at WARNING and exported in `tw_unsafe_settings_active`.
- **Fixed error responses.** Errors use the public messages and codes in `taowire.errors` (spec
  Appendix A); never include stack traces, signatures, payloads or internal paths. Every Appendix A
  error path has a test.
- **Untrusted input.** Every new parser of untrusted input gets Hypothesis property tests (and, in
  Go and Rust, a fuzz target).
- **Other languages.** The TypeScript, Go and Rust packages must pass every vector in
  `conformance/vectors/`. Vectors are generated by `conformance/generate.py`; never edit them by hand.
- **Documentation.** Every public API has a docstring and a page in `docs/`. Cite spec sections
  ("spec 8.4.3") where they help; `TAOWIRE_BUILD_SPEC.md` is the source of truth.
- No `TODO`/`FIXME` without an open GitHub issue it names; no commented-out code.
- No secrets, wallets or `.env` files in git. Tests use only well-known development keys (`//Alice`,
  the localnet's deterministic wallets).
- Python tests that need a real Redis read `TAOWIRE_TEST_REDIS_URL` (not a `TW_*` name: unknown `TW_*`
  variables are a startup error, in tests too).
- Benchmarks and test results report the real numbers. Never tune a test to make it pass.

## Pull requests

Keep a pull request to one topic, describe what changed and why, and list the checks you ran with
their results. User-visible changes get a line under `[Unreleased]` in [CHANGELOG.md](CHANGELOG.md).
